## Verdict

The site has broad event wiring, but the evidence is not yet decision-grade for promotion, shooting choices, or usability work. Several labels overstate what happened, ordinary exploration is incompletely recorded, and source/test classification can produce misleading audience conclusions.

1. **Confirmed defect — campaign source labels are forgeable.** [`share.ts:82`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/analytics/share.ts:82) accepts any short lowercase `?src=` string; the photo and album loaders write that raw value as a tagged arrival ([`photo loader:150`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/photo/[id]/+page.server.ts:150), [`tracker:83`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/analytics/tracker.ts:83)). A visitor can open a normal link with `?src=instagram` and create an “Instagram” arrival. Nino could wrongly conclude a promotion channel drove traffic. Smallest fix: distinguish a server-owned allowlist or signed campaign tag from unverified tags. Verify that a forged tag is excluded from trusted-channel reporting while a registered campaign tag remains attributable.

2. **Confirmed measurement limitation — search usability evidence is incomplete, and cache hits may skip it entirely.** The only durable search writes are text and jersey branches ([`explore loader:149`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/explore/+page.server.ts:149), [`:173`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/explore/+page.server.ts:173)); ordinary sport/category/play-type filtering falls through without one. Its separate filter store writes only to browser localStorage ([`filter-analytics:230`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/stores/filter-analytics.svelte.ts:230)). The same server route advertises a 60-second shared cache ([`explore loader:24`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/explore/+page.server.ts:24)), so a cache hit would not run its tracking code. Nino could conclude nobody searches for a type of shot when people instead filter for it, or undercount repeated identical searches. Smallest fix: emit one privacy-minimized, durable discovery event for filter changes and searches, independent of page-cache execution. Verify two isolated browsers performing the same filter/search produce two reportable events; confirm cache hits do not suppress them.

3. **Confirmed measurement limitation — automation without the special marker is audience traffic.** Context is `test` only with the signed request header, `operator` only with an allowed authenticated email, and otherwise `audience` ([`context.server.ts:16`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/analytics/context.server.ts:16)). Bot exclusion is only `isbot` ([`bot-detection.ts:10`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/analytics/bot-detection.ts:10)). I ran a pure local `isbot` check: a standard Chrome user agent returned `false`; Googlebot returned `true`. Thus a Playwright or operator browser using normal Chrome identity and no marker is recorded as audience. The later heuristic only marks a session after more than 500 photo views in a UTC day ([`analytics_unique_suspected_sessions.sql:4`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/supabase/migrations/20260929024500_analytics_unique_suspected_sessions.sql:4)). Nino could promote photos that test scripts or his own review favored. Smallest fix: make controlled-browser setup require the marker and record a test-run receipt. Verify a normal automated rehearsal is excluded only when marker setup succeeds.

4. **Confirmed defect — “view” is recorded before the image has loaded or become visible.** The photo page sends the view in its initial effect ([`photo page:29`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/photo/[id]/+page.svelte:29)) but its image only has an error handler ([`:200`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/photo/[id]/+page.svelte:200)). Lightbox does the same before its later `onload` ([`Lightbox:475`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/gallery/Lightbox.svelte:475), [`:625`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/gallery/Lightbox.svelte:625)); the detail modal also records first and has no load signal. A broken, blank, or immediately closed image can count as a viewed photo. Smallest fix: call the event `viewer_open`, or emit a separate rendered-view only after successful load plus visible time. Verify a forced image failure creates no rendered-view event.

5. **Confirmed defect — social “shares” include opening a composer, not sharing.** Both share components call `recordShare` immediately after `window.open` ([`ShareMenu:111`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/social/ShareMenu.svelte:111), [`SocialShareButtons:54`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/social/SocialShareButtons.svelte:54)); email is counted on `mailto:` click ([`SocialShareButtons:103`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/social/SocialShareButtons.svelte:103)). The visitor can cancel without publishing or sending. Nino could mistake composer opens for referrals or advocacy. Smallest fix: name these `share_intent`/`share_handoff`; reserve completed-share language for the Web Share success path or confirmed tagged arrivals. Verify cancelling an external composer does not raise a completed-share count.

6. **Confirmed coverage gap and limitation — download diagnostics do reach storage when received, but they neither cover every download surface nor prove a file arrived.** The endpoint validates and inserts a diagnostic ([`diagnostics endpoint:17`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/api/analytics/diagnostics/+server.ts:17), [`:28`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/api/analytics/diagnostics/+server.ts:28)). Direct, bulk, and favorites downloads call it, but ShareMenu’s branded-image download records only engagement ([`ShareMenu:44`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/social/ShareMenu.svelte:44), [`:124`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/social/ShareMenu.svelte:124)). Even covered single-photo downloads are explicitly only “requested,” not transfer completion ([`DownloadButton:67`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/components/photo/DownloadButton.svelte:67)). Nino could compare an incomplete failure rate or treat requests as received files. Smallest fix: normalize one requested/failed diagnostic call across every download entry point and label engagement as download-requested. Verify each surface produces exactly one diagnostic with its source; do not claim browser-save completion where it cannot be observed.

7. **Confirmed measurement limitation — collection loss is deliberately invisible.** Client tracking discards both network failures and endpoint responses ([`client.ts:24`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/analytics/client.ts:24)). The endpoint can return `503` when storage is unavailable ([`engagement endpoint:85`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/routes/api/engagement/+server.ts:85)), but no caller sees, retries, or counts that result. A valid favorite, open, share handoff, or download request can disappear with no distinction from zero demand. Smallest fix: retain a bounded client retry queue for failed responses and expose collector-delivery health separately from engagement. Verify a forced `503` queues one event and later stores exactly one after recovery.

### Facts safe to report

- Photo views are wired on the photo page, Lightbox, and detail modal; album opens are wired on album render; favorites and the listed download/share surfaces call the client collector.
- Event targets are parsed and a photo’s album is resolved authoritatively before insertion ([`collection-contract.ts:31`](/Users/nino/.codex/worktrees/analytics-clarity/nino-chavez-photography/src/lib/analytics/collection-contract.ts:31)).
- Text and jersey search diagnostics attempt durable storage with Cloudflare lifetime protection; download diagnostics insert when their endpoint receives them.
- Operator/test context is not accepted from request body fields.

### Unknowns

- Whether the current deployed edge cache serves these search pages from cache, and at what rate. A production cache trace would resolve this.
- Whether the deployed schema matches the migrations and whether diagnostics/events are actually arriving. A read-only database reconciliation would resolve this.
- Whether all controlled browser runs consistently carry the signed test marker or an operator session. Test-run receipts would resolve this.
- The real rate of analytics loss from ad blockers, offline transitions, and `503`s. A controlled failure rehearsal with delivery receipts would resolve this.
