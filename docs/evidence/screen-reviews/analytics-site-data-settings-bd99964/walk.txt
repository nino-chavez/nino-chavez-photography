Site report, data quality and settings walk, branch feat/analytics-site-data-settings at bd99964, 2026-10-06.
Method: this worktree's vite dev server (Node 22.22.0) reading production Supabase read-only, with the project's .env.local exported into the server process (node --env-file); no .env file was copied or edited. Playwright driving headless Chromium. Desktop 1440x900 full page; phone 375x812 at 2x in 812px parts (no capture is over 8,000 CSS px). The pages were opened at their internal addresses on 127.0.0.1 (the clean /data and /settings addresses need the real host, because the dev server's base path rejects them). No public gallery page was opened, and every run recorded its requests: none was a POST, none went to a public gallery page.

Labels in file names:
- "production": real production numbers. Cloudflare and PostHog are not configured locally, so the pages show their unavailable states honestly. On production the site scope has saved calculations, so signed-out visitors see the report-intelligence panel ("No actionable findings for this scope") at the foot of the site report.
- "synthetic-cloudflare": the Cloudflare page-load figures are INVENTED by a preload that answers api.cloudflare.com for the dev server only; the rest is production. "and-clicks": the link-click totals are also invented (counted-since moved to Sep 20, today's totals 1 and 2) so the populated layout can be seen. Do not quote any figure in these captures as site traffic.
- "simulated-problems": the dev server rewrites real Supabase responses (newest refresh 4 hours old, one open collection incident, Oct 3 and Oct 4 incomplete). Nothing was written anywhere.
- "owner-fixture" and "owner-record-fixture": NOT the real signed-in pages. Throwaway harness routes (src/routes/analytics/walk-settings and walk-sites, deleted before the receipt, never committed) rendered the real settings and site report page components with invented data (saved views; click figures, a Cloudflare read that is null and the owner's record-only state), and the browser stubbed the preferences and email-delivery endpoints. For the site report the record form was opened by pressing "Record what you did", as the owner would. They show layout of the owner views only. They do not exercise the load functions, the auth check, the saved-view actions or the snapshot lookup, and no shipped auth code was touched.

Gates: the overflow gate compares every element box with the viewport (hidden or clipped ancestors are not an excuse; a box inside a keyboard-focusable scroll region is excused only when that region itself fits). It was forced to fail once per width by planting an element wider than the viewport (the first scenario, both widths), then passed again after removal. Targets: links, buttons and fields under 44px in either direction, with links inside sentences reported separately (WCAG 2.5.8 inline exception); a card whose name link is stretched by ::after is measured as the card. Disclosures were opened before the gates ran. Scroll regions: Tab to the region, ArrowRight, wait 700 ms, scrollLeft must increase. At 1440 the data page's search and download evidence table fits its panel with no clipping and no scrolling. Text 200% sets the root font size to 200% and reruns the overflow gate.
Home links: with simulated problems, Home's Needs attention links were followed and each lands on an element that exists on the data page.
Console errors on Home were timeouts fetching album cover images from imagedelivery.net from this sandbox.
